# Voz local, micrófono y memoria del directo
Estado: propuesta para implementación basada en instrucciones del propietario. El diseño conserva TikTok Live integration and desktop platform scope.

## Meta de usuario
La streamer elige y descarga una voz local femenina en español latino. Puede activar el micrófono para dictar una frase: el programa la convierte a texto y Kokoro la lee con la voz elegida. Si la streamer no habla, el programa lee o responde comentarios según el modo. Las bienvenidas de nuevos espectadores siempre se mantienen en cola y nunca cortan la frase ya iniciada; después se reproducen, incluso si se acumulan. Las respuestas pueden usar una memoria breve y persistente del directo, editable y borrable.

## Decisiones
- Kokoro-82M ONNX int8 como TTS local predeterminado, voz española `ef_dora` (la única femenina española del modelo; no prometer región latinoamericana específica ni rasgos coquetos que el modelo no garantiza). Descargar desde un commit fijo con SHA-256 comprobado y guardar en directorio de datos local excluido de git. Descargar voces del release Kokoro fijado. Registrar licencia Apache-2.0 y URLs/versiones. UI permite preescuchar. Estilo coqueta/cálida es guía para respuestas de IA; la voz no ofrece control de estilo propio.
- Transcripción local opcional mediante `faster-whisper` tiny multilingüe, dispositivo CPU int8, VAD. Grabar micrófono explícitamente tras permiso del usuario, icono visible y botón apagar. Convertir cada utterance a texto y sintetizarla localmente con Kokoro. No guardar audio ni subirlo. Dictado local nunca se envía a Gemini u Ollama ni se graba como voz para clonación. Si al mismo tiempo llegan comentarios, retenerlos en cola. El usuario puede desactivar dictado y la app vuelve a leer comentarios al instante.
- Prioridades: un consumidor de audio serial. Saludo es de alta prioridad entre mensajes, jamás interrumpe audio activo. No se descarta un saludo por edad ni por cola llena; saludos entran en cola separada FIFO persistente para la sesión. Limitar duplicados por ID 300 s, pero cada espectador nuevo se saluda. Si el sistema cierra, saludos pendientes se intentan antes de otros eventos de la sesión activa. Comentarios son cola acotada y los antiguos pueden expirar. Tras una utterance del micrófono, se reanuda lectura de comentarios.
- El usuario configura actividad como evento de contexto («ahora juego Minecraft»), que reemplaza el contexto anterior. Memoria persistente SQLite local con tablas activities (texto, hora inicio/fin) y session_facts (hechos concisos aceptados por usuario, expiry configurable); solo se guardan al presionar guardar o confirmar una sugerencia, no inferencia silenciosa. Preguntas de comentarios se responden con contexto actual y últimos 10 hechos. Datos configurables: ver/exportar/limpiar; no se almacenan comentarios o audio por defecto. DB bajo user_data_dir, owner-only permissions, WAL; schema versionado. Text sent to Ollama local, never cloud; Gemini reply mode remains optional but discloses that context is sent to Google.
- TTS local no clave, no red tras descarga. Cloud Gemini TTS remains optional fallback only if user explicitly selects cloud mode; it must not silently take over when local model fails.

## Lógica de sonido y seguridad
Un `VoiceActivitySession` consume frames PCM 16k mono, detecta voz por RMS + silencio final configurable (600 ms), recorta segmentos máximo 15s, transcribe con faster-whisper tiny (no translation), y pone texto en la misma cola de reproducción; no llamar a LLM para dictated speech. Inactivity control: while mic speech or dictated audio is playing, pause incoming comment processing; after 2s silence resume. Start mic only after explicit button; status visibly "Micrófono activo". No auto launch mic. On device error, disable mic and log actionable error; comment reading resumes. Never store raw audio. Segment queue max 3; drop oldest dictation segment with notice, speech can be repeated. All QThread, model loading and inference cancel-aware; GUI responsive; one inference at a time.

## Acceptance
Fresh install downloads selected model one time (no key); offline voice preview passes; Spanish Latin text is pronounced intelligibly (user listens and chooses voice); mic transcription and local neural output work while app stays responsive; local questions use the current activity; join enqueued during active speech plays immediately after it and is not dropped; toggling mic off resumes comments; persistent activity/facts survive restart and clear/export works. API/LIVE test uses real account but no audio or comment data is stored.

## Sources and constraints
- Kokoro LiteRT community model card says Apache-2.0 and lists Spanish `ef_dora`, but app uses ONNX release for simpler desktop Python integration. Validate the ONNX files' provenance/hash before shipping.
- `faster-whisper` runtime and Tiny checkpoint are MIT; sounddevice is MIT; eSpeak-NG runtime is GPL-3.0 and must ship with notice/source access. These are documented in `THIRD_PARTY_NOTICES.md`. ASR is loaded only when the user starts the microphone; failures leave TTS available. Windows and macOS packaging still needs per-OS CI and manual microphone permission checks.
- Request says "coqueta"; ensure style is playful/warm, but avoid sexualized or intimate interaction. Don't imply model is trained as a personal voice clone.
- Don't download or redistribute user microphone/voice recordings. No cloning path is in scope.

## Alternatives and rationale
- Cloud TTS (Gemini) is already integrated and easy to preview but needs Internet and user key, sends narration text off-device, and can fail on quotas/latency. Keep as optional fallback; local is default for these voice features.
- Kokoro voices available locally include female Spanish `ef_dora`; selected over an English voice or voice cloning because it runs offline, is small enough for download-on-demand (88 MB int8 model + 28 MB voices), offers Spanish phonemes and does not require the user's voice sample. It is not guaranteed to be a Latin American variety; the user can preview before selection. Piper's `es_MX-claude-high` is a smaller-region-specific alternative but speaker is male. `ef_dora` selected for gender and Spanish quality, not a claim of region.
- ASR alternatives: OS cloud dictation is private only according to each OS service and inconsistent across OS; Whisper.cpp is MIT and can stream microphone but needs a native binary per OS; faster-whisper is a maintained Python option with multilingual tiny/ base model, CPU int8, but its CTranslate2 native dependency may not ship on every Python/OS combination. Choose faster-whisper optional with graceful support matrix; if native wheel is unavailable, retain the rest of app, show mic unavailable and allow manual text/TTS. Do not claim universal microphone support until matrix CI passes.
- Voice clone would require a clean sample, consent controls and substantially larger/less portable model. Not included: host speech is transcribed and spoken in the selected synthetic character voice. No identity imitation.

## Queue and session lifecycle
Join events are high-priority FIFO after the current audio. For each live room, SQLite holds a durable queue keyed by room/session ID and viewer ID with uniqueness constraint. SQLite join queue is append-only for a live room with no arbitrary row cap; a unique key coalesces repeat joins by the same viewer, while every distinct viewer receives a row. At 800 pending joins warn and pause ordinary comments while draining. Continue admitting join events until storage itself reports disk/full or I/O failure; show a persistent error and never erase an earlier queued viewer to admit a later one. Mark greeted only after playback ends; crash retries at least once, so a crash during playback may repeat a greeting after restart. Abrupt close retains rows for that room so reconnect to the same live room drains them. Once TikTok confirms a different room ID, remove records for previous rooms. Greeted rows older than 90 days are pruned; pending joins have no time expiry. Duplicate IDs are greeted once per room. If no room ID is supplied, the UI reports that persistent same-room deduplication cannot be guaranteed.

Mic capture is opt-in per user and per run; request OS permission only on first opt-in; visible indicator on only while stream captures, shutdown stops PortAudio, device loss stops stream and turns off indicator. Persist only local activity facts when explicit Remember context is enabled. By default transcripts are transient, never written to activity logs, crash reports, database or cloud. If user asks local AI to update context from speech, the app stores only a concise generated summary in SQLite (no transcript/audio) and shows it in the context panel for correction/undo. Add a clear-memory/export button. SQLite path via platformdirs; permissions: POSIX 0700 dir, 0600 DB/WAL; Windows user-only ACL inherited from LocalAppData; macOS user-only Application Support. Clear/export checkpoints WAL and securely removes db, WAL, SHM files. Expired facts purged on each app start and every 10 min. Activity replacement closes previous row with end time in the same transaction before inserting current. User must affirm remote transfer in advance before Gemini mode is allowed with activity context; Ollama and TTS are local and do not transfer context.

The ONNX model uses fixed Hugging Face commit `srsuzume/tts@391dfc06b9e9b3dc480457c79f74b2a9cb8058c4`; its Xet pointer publishes SHA-256 `6e742170d309016e5891a994e1ce1559c702a2ccd0075e67ef7157974f6406cb`. That digest matches the locally downloaded file and the original `thewh1teagle/kokoro-onnx` v1.0 release asset. The voice vectors use the independent Hugging Face copy `PatnaikAshish/kokoclone@64dda9eada5b036deede1faf29715d3145b5b703`; its Git LFS pointer publishes SHA-256 `bca610b8308e8d99f32e6fe4197e7ec01679264efed0cac9140fe9c29f1fbf7d` and exact size 28,214,398 bytes. Both source repositories label their material Apache-2.0. The GitHub model tag is signed at commit `6843c53` (GPG key ID `B5690EEEBB952194`); this verifies source identity but does not cryptographically bind release assets, so the app pins both independent immutable Hugging Face revisions and checks published digest and exact byte size in `narrador/voice-models.json`. Any asset update requires an independently verified digest, changed manifest, and code review. Kokoro runtime MIT; eSpeak-NG GPL-3.0 notice and source access included. Voice data stays outside the app installer and downloads on demand. `faster-whisper` code and its Tiny multilingual checkpoint are MIT; the checkpoint is pinned to Hugging Face commit `Systran/faster-whisper-tiny@d90ca5fe260221311c53c58e660288d3deb8d356`. Linux x86_64 tested in the current environment; Windows and macOS bundles require their own CI and manual microphone permission checks. If a native runtime/device fails, the UI reports that while keeping TTS usable.

## Privacy and acceptance additions
Mic speech stays local, audio is immediately discarded after inference; no transcript enters the log/database by default. Activity summary can persist only when Remember context is on and is visibly reviewable. The activity and facts are included in local Ollama prompt; Gemini requires opt-in confirmation for those fields as part of its sent context. Tests cover database replacement, expiry and full deletion of DB/WAL/SHM; queue bursts above 800 persist every distinct viewer, pending join retry after app restart in same room, dedup by room/viewer; injected storage failure shows persistent error and does not falsely claim delivery; mic device loss and stop lifecycle; microphone transcript never cloud/log by default; repeated audio while active is not interrupted; fresh `ef_dora` voice preview and region-label disclosure.
