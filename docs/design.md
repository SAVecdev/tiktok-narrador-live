# TikTok Narrador Live
Author: SAVecdev. Date: 2026-11-15. Status: implementation authorized by project owner; independent review pending.

## Overview and problem
This is a new, empty project. A streamer needs a desktop app that receives TikTok LIVE comments and join events, answers comments aloud and welcomes viewers. The app must run on Windows, Linux and macOS. People download a packaged executable from GitHub Releases and enter their own credentials in the GUI; no .env, Python installation or terminal is required for packaged users.

## Goals and boundaries
Spanish GUI, editable voice gender, language, pitch, speed and volume; preview button; start/stop; simulated comments and joins; bounded log; optional Gemini answers and comment reading; greeting cooldown. Replies are local audio, not posted chat messages. OBS can capture desktop audio. Internet access and valid API credentials are prerequisites for cloud features. Open-source software does not imply free third-party API usage. No real keys are shipped. No unattended publishing of chat messages, account login or password collection.

## User journeys
1. Download and extract the release for the correct OS/architecture, launch app, use Demo to see simulated comments and greetings without credentials. Demo emits text and optionally local system speech; it never makes cloud calls.
2. Enter Google Cloud Text-to-Speech key and optional Gemini key; enter TikTok handle and optional Euler Stream signing key; select settings and Save. Credentials stay in memory unless remember is checked. Remember uses only a secure OS credential vault; failure visibly falls back to session-only, never plaintext. Normal preferences use a JSON file in the OS app-config directory.
3. Preview voice makes one Google TTS request and plays the result. Start subscribes via the third-party TikTokLive Python client to comment and join events. The app says connected only after a real connect event. Disconnect/offline errors are visible. User reconnects manually; no surprise reconnect costs.
4. Incoming events enter a queue of 20; newest overflow is dropped with a rate-limited visible count. Events older than 30 seconds are skipped. Join greetings repeat at most once per person per 300 seconds. Comment cooldown per person is 10 seconds. User IDs key cooldowns, not display names. Identity caches are bounded to 2000 entries and reset each session.
5. Stop discards queued work, invalidates in-flight results, cancels connection/tasks and stops audio immediately. Start remains disabled until worker cleanup completes. Closing waits asynchronously for worker cleanup; never destroys a running thread.

## Architecture
Python 3.12+ with PySide6 (Qt GUI and multimedia). GUI owns audio playback and widgets. A QThread runs an asyncio loop with httpx network requests and TikTokLive. Signals carry event/status/text/audio to the GUI, never raw exceptions containing keys. One consumer generates at most one response and synthesizes at a time and waits for playback acknowledgement before next item. A monotonically increasing session identifier prevents late audio/signals reaching a newer session. API operations have finite timeouts; cancellation is cooperative. Audio is WAV in a temporary file cleaned after playback. Demo uses Qt system TTS when installed, otherwise text-only is explicitly indicated.

Google Cloud TTS REST accepts plain text, language, gender and optional named Standard voice; audioConfig LINEAR16, speakingRate 0.25..4, pitch -20..20. Only Standard voices are offered by the catalogue to preserve pitch controls. Gemini uses generateContent with a model identifier editable in GUI, catalogue refresh via models.list and a conservative response length limit. Input comments are untrusted data; instructions live in systemInstruction. Gemini errors fall back to reading the comment with a visible notice. Cloud failures never trigger unlimited retries. TTS errors skip audio visibly. Global minimum interval 2 seconds and per-session maximum 100 cloud speech items (preview excluded); restart resets budget. Disabled features make no API calls. Names max 60 and comments max 300 characters; control characters and URLs stripped; optional blocked words apply before external calls. Greeting template replaces only {usuario} literally, never evaluates format expressions.

TikTokLive is an unofficial integration, may break with TikTok changes, and cannot guarantee delivery of every join. Euler signing key is configured via its documented WebDefaults option. No arbitrary endpoint accepts secrets. Only the known Google and Euler/TikTok endpoints are used. Anonymous demo uses no live provider. Logs remain in RAM, max 300 lines, never saved automatically. User content goes to Google only when relevant cloud features are used. Credentials are sent only to their matching provider.

## Alternatives and decisions
Qt chosen for native desktop packaging and no local HTTP server. Electron would add a JavaScript runtime and larger packages. Browser-only app would complicate credential storage and desktop audio. PyInstaller bundles Python and dependencies separately per OS; Windows x64, Linux x64 (Ubuntu 22.04+ baseline), macOS arm64 and x64 are release targets. Unsigned builds may trigger OS warnings; signing is not provisioned. Linux needs a graphical session and system audio libraries. Dependency licenses must accompany distributions; use AGPL-3.0-or-later for this project to match the live-client dependency. No platform compatibility claim until corresponding CI builds succeed.

## Detailed Implementation Plan
- narrador/config.py: Settings dataclass, validate(), load_settings(path), save_settings(settings,path); SecretStore.load/save/forget provider keys via keyring secure platform backends only. Atomic JSON writes contain only allowlisted non-secret fields. Malformed settings restore defaults with visible warning.
- narrador/core.py: Event(kind,user_id,name,text,created), Policy.accept(event,now), bounded caches and normalization. No Qt/network dependencies so deterministic unit tests can exercise floods, cooldowns, filtering and templates.
- narrador/services.py: GoogleServices async voices/models/reply/synthesize methods with injected httpx client and explicit request contracts. ProviderError contains fixed safe Spanish messages keyed by HTTP status (401/403 credentials, 429 quota, 5xx availability). No request URLs or raw exception strings in log.
- narrador/worker.py: SessionWorker(QThread) with signals status/log/spoken/audio/finished, run() owns asyncio.run; submit simulation/start/stop/playback acknowledgement thread-safe. TikTok event handlers normalize and enqueue. Network cancellation and playback wait timeouts prevent hanging shutdown.
- narrador/app.py and __main__.py: Spanish main window, live controls, settings tabs, masked API key fields, remember toggle, test buttons, log, audio player, demo speech, orderly lifecycle. One session at a time including voice previews/catalogue requests. Settings controls disabled during active session; runtime stop/volume remain usable. Save validates before writing.
- tests/: pure core tests, mocked Google service tests, settings/keyring tests, offscreen Qt lifecycle tests with synthetic adapters, offline smoke screenshot.
- pyproject.toml, requirements lock, run.py, packaging spec: pinned reproducible dependencies, PyInstaller onedir windowed executable, standard-library license notices bundled.
- .github/workflows/: CI lint/test on three OS families, build on manual dispatch and version tags; tag workflow publishes archives and checksums on GitHub Releases. GitHub token minimally scoped. README Spanish launch/API setup/limitations/troubleshooting and LICENSE.
