# TikTok Narrador Live
Author: SAVecdev. Date: 2026-11-15. Status: implementation authorized by project owner; independent review pending.

## Overview and problem
This is a new, empty project. A streamer needs a desktop app that receives TikTok LIVE comments and join events, answers comments aloud and welcomes viewers. The app must run on Windows, Linux and macOS. People download a packaged executable from GitHub Releases and enter their own credentials in the GUI; no .env, Python installation or terminal is required for packaged users.

## Goals and boundaries
Spanish GUI, editable voice gender, language, pitch, speed and volume; preview button; start/stop; simulated comments and joins; bounded log; Ollama local answers and Gemini TTS speech; greeting cooldown. Replies are local audio, not posted chat messages. OBS can capture desktop audio. Internet access and valid API credentials are prerequisites for cloud features. Open-source software does not imply free third-party API usage. No real keys are shipped. No unattended publishing of chat messages, account login or password collection.

## User journeys
1. Download and extract the release for the correct OS/architecture, launch app, use Demo to see simulated comments and greetings without credentials. Demo emits text and optionally local system speech; it never makes cloud calls.
2. Enter one Google AI Studio key for Gemini TTS and optional Gemini replies; enter TikTok handle and optional Euler Stream signing key; select settings and Save. Credentials stay in memory unless remember is checked. Remember uses only a secure OS credential vault; failure visibly falls back to session-only, never plaintext. Normal preferences use a JSON file in the OS app-config directory.
3. Preview voice makes one Google TTS request and plays the result. Start subscribes via the third-party TikTokLive Python client to comment and join events. The app says connected only after a real connect event. Disconnect/offline errors are visible. User reconnects manually; no surprise reconnect costs.
4. Incoming events enter a queue of 20; newest overflow is dropped with a rate-limited visible count. Events older than 30 seconds are skipped. Join greetings repeat at most once per person per 300 seconds. Comment cooldown per person is 10 seconds. User IDs key cooldowns, not display names. Identity caches are bounded to 2000 entries and reset each session.
5. Stop discards queued work, invalidates in-flight results, cancels connection/tasks and stops audio immediately. Start remains disabled until worker cleanup completes. Closing waits asynchronously for worker cleanup; never destroys a running thread.

## Architecture
Python 3.12+ with PySide6 (Qt GUI and multimedia). GUI owns audio playback and widgets. A QThread runs an asyncio loop with httpx network requests and TikTokLive. Signals carry event/status/text/audio to the GUI, never raw exceptions containing keys. One consumer generates at most one response and synthesizes at a time and waits for playback acknowledgement before next item. A monotonically increasing session identifier prevents late audio/signals reaching a newer session. API operations have finite timeouts; cancellation is cooperative. Audio is WAV in a temporary file cleaned after playback. Demo uses Qt system TTS when installed, otherwise text-only is explicitly indicated.

Gemini TTS uses the Interactions API with gemini-3.8-flash-tts, a Google AI Studio key, a prebuilt voice and style metadata; unary output is WAV. Only Standard voices are offered by the catalogue to preserve pitch controls. Gemini uses generateContent with a model identifier editable in GUI, catalogue refresh via models.list and a conservative response length limit. Input comments are untrusted data; instructions live in systemInstruction. Gemini errors fall back to reading the comment with a visible notice. Cloud failures never trigger unlimited retries. TTS errors skip audio visibly. Global minimum interval 2 seconds and per-session maximum 100 cloud speech items (preview excluded); restart resets budget. Disabled features make no API calls. Names max 60 and comments max 300 characters; control characters and URLs stripped; optional blocked words apply before external calls. Greeting template replaces only {usuario} literally, never evaluates format expressions.

TikTokLive is an unofficial integration, may break with TikTok changes, and cannot guarantee delivery of every join. Euler signing key is configured via its documented WebDefaults option. No arbitrary endpoint accepts secrets. Only the known Google and Euler/TikTok endpoints are used. Anonymous demo uses no live provider. Logs remain in RAM, max 300 lines, never saved automatically. User content goes to Google only when relevant cloud features are used. Credentials are sent only to their matching provider.

## Alternatives and decisions
Qt chosen for native desktop packaging and no local HTTP server. Electron would add a JavaScript runtime and larger packages. Browser-only app would complicate credential storage and desktop audio. PyInstaller bundles Python and dependencies separately per OS; Windows x64, Linux x64 (Ubuntu 22.04+ baseline), macOS arm64 and x64 are release targets. Unsigned builds may trigger OS warnings; signing is not provisioned. Linux needs a graphical session and system audio libraries. Dependency licenses must accompany distributions; use AGPL-3.0-or-later for this project to match the live-client dependency. No platform compatibility claim until corresponding CI builds succeed.

## Review clarifications
Comment handling uses one exclusive mode: ignore, read aloud, or AI answer. AI-answer mode reads the original comment as a documented fallback if generation fails; it never reads and answers twice. Greetings have an independent toggle. Euler Stream signs the connection request used to subscribe to TikTok's live stream; its optional personal key provides the user's service quota. Without a key, TikTokLive uses its default public signing access when available. Offline/signing/quota errors are reported and require manual retry; no promise of free availability.
Credential persistence: unchecking Remember or clearing a provider field deletes its existing vault entry on Save. Replacement overwrites only that provider. Failed deletion is reported explicitly; the UI never claims forgotten until confirmed. Vault operation failures do not prevent session-only use. Cloud budget reserves one item before any generation/synthesis attempt, including failures, with at most 100 admitted items per session. Once exhausted queued items are dropped and the log asks the user to stop and intentionally start a new session. Gemini uses maxOutputTokens=180 and final plain text truncated at 400 characters before speech.

## EGM code review resolution
A fresh-context Goldfish reviewed the implemented source and identified three issues: Gemini voice IDs were filtered/rejected; privacy copy omitted data transfer in Gemini reply mode; fabricated voice gender/language metadata. All three are corrected: actual Gemini voice IDs are selectable and accepted, UI explains Gemini receives replies when selected, and voice catalogue makes no unsupported gender/language claims. Tests cover the local API and updated synthesis contract.


## EGM follow-up: contextual replies and speech errors
The streamer can save a short activity description (for example, the game being played). It is added to the system context for Ollama or Gemini replies. In answer mode, if generation fails, the app skips that event instead of speaking the raw viewer comment, preventing the repeated-comment symptom. Provider errors now show safe actionable messages. Gemini TTS requests allow up to 90 seconds because audio generation can take longer than a short text request; the UI reports synthesis failures without claiming success. Added tests verify context reaches Ollama and a failed answer is not read aloud.
